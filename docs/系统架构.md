# 系统架构

OfferMate AI 采用前后端分离架构。前端负责页面展示和交互，后端提供 REST API 与 WebSocket 通信能力，核心数据存储在 MySQL，缓存、异步消息、搜索、文件存储和 AI 能力由独立基础设施支撑。

## 总体架构

```text
┌────────────────────────────┐
│        Vue3 PC Web          │
│  Vite / Element Plus        │
└──────────────┬─────────────┘
               │ HTTP / WebSocket
┌──────────────▼─────────────┐
│     Spring Boot Backend     │
│ Controller / Service / DAO  │
└──────┬──────┬──────┬───────┘
       │      │      │
       │      │      ├──────────── MinIO
       │      │      │             文件对象存储
       │      │
       │      ├────────────────── Elasticsearch
       │      │                    岗位全文搜索
       │
       ├───────────────────────── Redis
       │                          缓存 / 限流 / 黑名单 / 锁
       │
       ├───────────────────────── RabbitMQ
       │                          异步通知 / AI 日志
       │
       ├───────────────────────── MySQL
       │                          核心业务数据
       │
       └───────────────────────── DashScope / Qwen
                                  Spring AI / LangChain4j
```

## 后端分层

后端代码包名以 `com.offermate` 为根包，整体采用经典三层结构：

```text
controller  接口层，负责接收请求和返回 Result
service     业务层，负责业务规则、权限校验、事务控制
mapper      数据访问层，基于 MyBatis-Plus 操作数据库
entity      数据库实体
dto         请求参数对象
vo          返回视图对象
config      Redis、MQ、ES、MinIO、WebSocket、AI 等配置
interceptor JWT 登录拦截器
websocket   聊天 WebSocket 处理
mq          RabbitMQ 生产者、消费者、消息 DTO
es          Elasticsearch 文档、索引和搜索服务
util        工具类
```

## 认证与权限架构

1. 用户登录成功后，后端生成 JWT。
2. 前端请求受保护接口时，在请求头携带：

   ```text
   Authorization: Bearer token
   ```

3. `JwtLoginInterceptor` 解析并校验 token。
4. 校验成功后，将当前用户信息放入 `UserContext`。
5. 请求结束后清理 ThreadLocal，避免内存泄漏。
6. Service 层根据当前用户角色和资源归属进行权限判断。

角色约定：

| role | 角色 |
| --- | --- |
| 1 | 求职者 |
| 2 | 招聘者 |
| 3 | 管理员 |

## Redis 使用场景

| 场景 | 说明 |
| --- | --- |
| 岗位缓存 | 缓存岗位分页和详情，减少数据库压力 |
| Token 黑名单 | 用户退出后旧 token 失效 |
| 投递锁 | 防止短时间重复点击投递 |
| AI 限流 | 控制用户每日 AI 调用次数 |
| 聊天未读数 | 加速会话未读数量展示 |

Redis 异常时，核心业务尽量降级到数据库逻辑，避免因为缓存不可用导致主流程完全失败。

## RabbitMQ 使用场景

| 队列 | 说明 |
| --- | --- |
| 投递通知队列 | 求职者投递后异步通知招聘者 |
| 面试通知队列 | 面试邀请、接受、拒绝、取消后异步通知 |
| 企业审核通知队列 | 企业审核结果通知招聘者 |
| 岗位审核通知队列 | 岗位审核结果通知招聘者 |
| AI 日志队列 | AI 调用日志异步写库 |

生产者发送失败只记录日志，不影响投递、审核、AI 等主业务成功。

## Elasticsearch 搜索架构

岗位数据在 MySQL 中作为主数据，Elasticsearch 作为搜索索引。

同步策略：

- 岗位审核通过且上架后写入 ES
- 岗位修改后更新 ES 文档
- 岗位删除或下架后删除 ES 文档
- 管理员可触发全量同步

搜索接口只返回：

- `status = 1`
- `auditStatus = 1`

即已上架且已审核通过的岗位。

## WebSocket 聊天架构

WebSocket 地址：

```text
/ws/chat?token=jwt-token
```

握手阶段通过 token 识别用户身份。后端维护在线用户连接，发送文本消息时：

1. 校验会话是否存在。
2. 校验发送人和接收人是否为会话参与者。
3. 消息落库。
4. 更新会话最后一条消息。
5. 如果接收人在线，实时推送。
6. 更新接收方未读数。

## AI 架构

项目同时保留 Spring AI 与 LangChain4j 两套 AI 接入方式：

- Spring AI：简历优化、面试题生成、岗位描述生成
- LangChain4j：岗位匹配、模拟面试多轮上下文、评分与报告

AI 调用统一做：

- 权限校验
- Redis 每日限流
- Prompt 长度限制
- 异常兜底
- 调用日志记录
